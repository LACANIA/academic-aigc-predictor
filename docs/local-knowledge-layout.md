# 本地知识库结构与课题组迁移

## 构建后生成什么

执行初始化、配对导入、页面复核和构建后，本地知识目录通常如下。名称仅用于说明，实际案例路径以 `knowledge.json` 为准。

```text
knowledge/
├── knowledge.json                 # 当前预检配置：路径、哈希及家族登记
├── rules.md                       # 经验规则
├── cases.json                     # 初始化生成的空案例文件
├── workspace.json                 # 导入与复核登记
├── generations/
│   └── <生成版本标识>/
│       └── cases.json             # 当前版本的已复核案例
└── imports/
    └── <配对标识>/
        ├── import.json            # 版本配对和来源记录
        ├── geometry.json          # 高亮几何证据
        ├── REVIEW.md              # 复核说明
        ├── review.template.json   # 复核填写模板
        └── reviews/               # 已提交的复核记录
```

使用 `--render` 时还会生成报告页面图像。构建后预检使用配置指向的版本化案例，根目录的初始化空文件不能代替它。

`knowledge.json` 使用 `portable-knowledge-1` 格式：`root` 指定知识根目录，`cases_file` 和 `rules_file` 是根目录以内的相对路径，两个 SHA-256 字段绑定实际文件。程序自动生成的配置通常使用 `root: "."`，相对于配置自身所在目录解析。配置本身不包含完整案例或规则，使用时需要能访问它引用的文件。

## 在课题组内迁移用于预检

先确认案例原文、报告证据和相关研究资料允许在成员之间使用，并确认可以进入所使用的宿主模型上下文。知识库可能包含未发表论文摘录，不能因在组内使用就自动视为可以公开。

1. 在接收电脑安装 Skill 及声明的 Python 依赖。
2. 将 `knowledge.json`、它引用的案例版本文件和规则文件复制到独立的本地知识目录，保留相对目录关系。不要放进公开仓库或 Skill 安装目录。
3. 核对 `root`：相对根目录通常可以随目录整体迁移，绝对根目录需要指向接收电脑的实际位置。案例及规则文件内容未改变时，原哈希保持不变；不一致时先核查来源和完整性。
4. 使用新电脑上的 Python 路径和迁移后的配置路径调用预检，明确传入 `--knowledge`。程序会检查配置、文件哈希及内容格式；同家族案例过滤继续适用。

这属于现有配置和读取接口支持的资料迁移，没有一键导出或自动重定位所有研究证据的功能。迁移后的案例范围与使用条件应如实说明，不能声称等同于经过独立验证的公共知识库。

## 迁移后继续建库

仅用于预检的配置与案例副本，不包含完整建库工作区的全部证据。`knowledge verify --workspace` 还会核对导入、几何、复核及其登记的原论文和报告路径；只复制配置和案例，不能宣称完成工作区级核验。

需要继续导入、复核或重新构建时，应保留完整工作区及获准使用的原始资料。现有导入记录包含原文件路径，跨电脑迁移后这些路径可能不可用；此时应在新的本地工作区明确提供资料路径、重新导入与复核，保留旧证据，不直接修改旧记录或哈希来绕过检查。

知识库用于整理可追溯的历史检测观测，没有训练独立模型，也不保证正式检测分数。团队内部迁移与向公共仓库贡献资料应分别确认授权范围。
